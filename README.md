I'm a backend engineer on a multi-tenant SaaS product built with Django, Vue.js and PostgreSQL, which also runs a production RAG and LLM platform. I ship features and fix production bugs across it, and I've studied its architecture in depth. Now I'm building these systems myself from scratch, and working toward LLM inference and serving.

### 🏗️ Production systems I know end to end

Team-built systems in the product I work on. I've worked in their code and can walk through how they're designed and why.

- **RAG and agent platform**<br>
  Retrieval-augmented generation on PostgreSQL + pgvector, with multi-provider LLM routing, embeddings, tool orchestration and agent workflows.
- **Postgres-native task executor**<br>
  Distributed task execution built entirely on PostgreSQL (queuing, fan-out/join, idempotency) with no Celery or Redis.
- **Query performance work**<br>
  An analytics query taken from 239 s to 0.9 s with rollup tables, indexing, JSONB and full-text search, and N+1 elimination that cut queries per request from 500+ to ~5–10.

### 🌱 Currently learning

- **Python concurrency in practice:** threads, the GIL, multiprocessing, asyncio, and the failure modes behind them
- **Shipping my own software:** Docker, CI/CD with GitHub Actions, deploying and running a service myself
- **Building RAG and agents from scratch:** chunking, embeddings, pgvector search and tool calling, without frameworks first

### 🧠 Interests

- **LLM inference:** serving engines (vLLM), continuous batching, KV-cache management, quantization
- **Retrieval quality:** chunking, hybrid search, reranking, evaluation for RAG
- **Agents:** reliable tool calling, orchestration, failure modes
- **Databases as infrastructure:** using PostgreSQL for queues, vectors and search
